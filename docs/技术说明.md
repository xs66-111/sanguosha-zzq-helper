# 技术说明

## 一、整体结构

```
Steam《三国杀》(CEF 套壳, Sgsc10th.exe)
        │  --remote-debugging-port=9222
        ▼
CDP(Chrome DevTools Protocol) ── game_overlay/inject.mjs / launch.ps1
        │  注入
        ▼
游戏页面：data/tavernchess.js + data/lineups.js + data/stats.js + game_overlay/overlay.js
        │  只读游戏内部对象，绘制浮窗；记录对局
        ▼
records/matches.json ── tools/summarize_records.py ── data/stats.js（回灌给浮窗）
```

## 二、配置数据的获取（离线，一次性）

1. 下载 `https://web.sanguosha.com/10/pc/res/config/Config.sgs`（整包配置）与 `https://web.sanguosha.com/10/pc/libs/min/resc`（解密用 wasm）。
2. `.sgs` 是 OFB 流密码加密；`resc` 里导出函数 `a` 就是解密器（客户端里叫 `CtrUtil.Ctr.Ofb_Dec`）。
3. `tools/update_data.py`：用 `wasmtime` 实例化 wasm，把文件按 16 字节补零后原地解密；输出可能是 zip/gzip/JSON，按魔数处理。
4. 取出 `TavernChessConfig.sgs` → 明文 JSON，摘出：
   - `ChessConf` 棋子（星级/攻击/体力/技能/金色版本）
   - `ChessGeneralConf` + `ChessGeneralSkillConf` 主公与技能
   - `ChessSpellConf`、`ChessWeaponConf`(+`ChessWeaponSkillConf`) 锦囊与装备
   - `ChessShopConf` 营帐等级/升级价/格子数/各星级刷新权重
   - `ChessRankConf` 各星级在公共池里的份数
   - `ChessGlobalConf` 经济参数（刷新/购买/出售/利息/装备回合/阵亡结算上限）
   - `ChessModeSeasonConf` 赛季与阵营池
   - 全历史 `ChessID → 名称/势力/星级`（阵容库会出现往期棋子）

## 三、游戏内状态读取（浮窗）

场景定位：遍历 `Laya.stage`，按权重挑 `TavernChessGameScene`(100) / `TavernChessHallScene`(80) / `TavernChess*`(10)，带 `manager` 再加分。

manager 上读到的字段（都做了大小写/多候选兜底）：

| 用途 | 字段 |
|---|---|
| 本局阵营 | `chessMinionTypList` / `ChessMinionTypList` |
| 商店 | `shopGoods` / `ShopGoods`（每项 `goodsID/chessID/spellID`） |
| 手牌 | `selfInfo.handChess` / `HandChess` |
| 上阵 | `selfInfo.lineUpChess`（带 `pos`）/ `selfInfo.lineUp` + `selfInfo.Chess` |
| 虎符 / 营帐 / 升级价 | `CoinNum` / `ShopCurLevel` / `ShopLevelUpCost`（已含主公技能折扣） |
| 主公 / 血量 | `GeneralID` / `HP` / `HPLimit` |
| 八家 | `playerList`（他人只有 hp/等级/主公/装备） |
| 本轮对手 | `battlePlayerInfo`；战斗中 `enemyPlayerInfo.Chess` 或舞台 `enemyUIs[].ServerInfo.chessID` |
| 三选一 | `waitSelectCardArr` / `WaitSelectCards` / `waitSelectEquiments` |

> 所有读取都在 try/catch 里；异常写进 `window.__zzqError`，方便出问题时自查。

## 四、官方阵容库接口

```
GET/POST https://yjcm-zzq.sanguosha.com/v1/recommend
  account=0&country=0&tag=1&general_id=0&timestamp=<unix>&sign=<md5>
sign = md5( 按 key 升序拼接的 "key=value" + apiKey )
apiKey = 见 tools/fetch_lineups.py（客户端 main.min.js 中的静态串）
```

返回每条阵容：`plan_id / name / tag / early·middle·last / general / mount·weapon·armor /
win_rate / front_rate / users / likes / general_note·front_note·middle_note·last_note·weapon_note`。

客户端里对应文案：`胜率：{0}%   吃鸡率：{1}%   应用人数：{2}`。

## 五、对局记录器

- 采样频率 700ms（与面板同一循环），按"回合"聚合：虎符曲线、营帐、血量、商店出现过的牌、自己的阵容。
- 结束判定：`isAllGameOver / bGameGameOver / isGameOver` 为真，或离开自走棋场景（`archiveCurrent('离开自走棋')`）。
- 名次：优先取 `selfInfo.rank` 等字段，取不到就用"结束时存活人数"兜底（自己活着=1）。
- 冠军判定（汇总时）：一局结束时**唯一 `dead=false` 的那家**就是冠军；用 `name / generalID` 去匹配记录里观察到的对手阵容。

## 六、注入器的两种实现

| 文件 | 说明 |
|---|---|
| `game_overlay/launch.ps1` | 纯 PowerShell（ClientWebSocket 手写 CDP），零依赖；`启动并注入.bat` 调用它 |
| `game_overlay/inject.mjs` | Node 版（全局 WebSocket + fetch），适合喜欢 node 的人；`push.mjs` 只管热更新 |

两者都会：找 exe → 带调试端口启动 → 注入 → 每 10 秒把对局记录拉回 `records/matches.json` → 持续监视新页面并补注入。

## 七、已知限制

- 客户端**不下发**对手阵容与公共池实时状态：对手只能靠主公推断 + 战斗期抓取；牌池只能给份数与"本局见过几次"。
- 面板依赖游戏内部对象名，官方大版本重构可能失效；失效时改 `overlay.js` 的 `readState()` / `findManager()` 即可，数据与评分部分是独立的。
- 记录里含玩家昵称，属于个人数据，仓库里默认不提交（见 `.gitignore`）。
